  EXECUTIVE SUMMARY
================================================================================

This report documents the integration of Xilinx IP cores for debug and memory
access in the Slime Simulator FPGA design. The debug infrastructure enables:

  ✓ Reading trail memory via JTAG (no soft processor required)
  ✓ Monitoring internal signals in real-time
  ✓ Capturing waveforms for debugging
  ✓ Controlling simulation execution from host PC
  ✓ Regression testing by comparing FPGA output with Python simulator

The implementation uses three key Xilinx IP cores:
  1. JTAG-to-AXI Master - Provides AXI memory access via JTAG
  2. VIO (Virtual I/O) - Interactive signal monitoring and control
  3. ILA (Integrated Logic Analyzer) - Waveform capture

1. JTAG-TO-AXI MASTER IP
────────────────────────────────────────────────────────────────────────────

  IP Name:           debug_jtag_axi
  Xilinx Part:       xilinx.com:ip:jtag_axi:1.2
  Module Name:       debug_jtag_axi
  Location:          ./vivado_project_debug/ip/debug_jtag_axi/

  Configuration:
    Protocol:        AXI4-Lite
    Data Width:      32-bit
    Address Width:   32-bit
    ID Width:        1-bit
    Clock:           100 MHz (system clock)
    Read Queue:      4 transactions
    Write Queue:     4 transactions

  Interface Signals:
    Clock:           aclk (connected to clk_100mhz)
    Reset:           aresetn (connected to rst_n)

    AXI Master Interface:
      Read Address:   m_axi_araddr[31:0]
                      m_axi_arvalid
                      m_axi_arready
      Read Data:      m_axi_rdata[31:0]
                      m_axi_rresp[1:0]
                      m_axi_rvalid
                      m_axi_rready
      Write Address:  m_axi_awaddr[31:0]
                      m_axi_awvalid
                      m_axi_awready
      Write Data:     m_axi_wdata[31:0]
                      m_axi_wstrb[3:0]
                      m_axi_wvalid
                      m_axi_wready
      Write Response: m_axi_bresp[1:0]
                      m_axi_bvalid
                      m_axi_bready

  Purpose:
    Provides AXI-Lite master interface accessible via JTAG. Host PC can
    issue read/write transactions through Vivado Hardware Manager or Python
    scripts to access trail memory and control registers.

  Resource Usage (estimated):
    LUTs:    ~500
    FFs:     ~600
    BRAM:    0


2. VIO (VIRTUAL I/O) IP
────────────────────────────────────────────────────────────────────────────

  IP Name:           debug_vio
  Xilinx Part:       xilinx.com:ip:vio:3.0
  Module Name:       debug_vio
  Location:          ./vivado_project_debug/ip/debug_vio/

  Configuration:
    Clock:           100 MHz (system clock)
    Input Probes:    3
    Output Probes:   4

  Input Probes (Design → Host):
    probe_in0 [1]:   capture_done      - Capture completed at frame boundary
    probe_in1 [32]:  frame_count       - VGA frame counter
    probe_in2 [8]:   trail_data        - Trail memory read data

  Output Probes (Host → Design):
    probe_out0 [1]:  capture_trigger   - Trigger capture sequence
    probe_out1 [1]:  sim_freeze        - Freeze simulation for stable reads
    probe_out2 [1]:  read_enable       - Enable VIO-driven memory access
    probe_out3 [19]: read_addr         - Memory address for VIO reads (0-307199)

  Purpose:
    Provides virtual I/O for interactive debugging via Vivado Hardware Manager.
    Allows monitoring frame count, triggering captures, freezing simulation,
    and spot-checking memory contents without full AXI transactions.

  Resource Usage (estimated):
    LUTs:    ~200
    FFs:     ~250
    BRAM:    0


3. ILA (INTEGRATED LOGIC ANALYZER) IP
────────────────────────────────────────────────────────────────────────────

  IP Name:           debug_ila
  Xilinx Part:       xilinx.com:ip:ila:6.2
  Module Name:       debug_ila
  Location:          ./vivado_project_debug/ip/debug_ila/

  Configuration:
    Clock:           100 MHz (system clock)
    Number of Probes: 8
    Capture Depth:   4096 samples
    Storage Qual:    Enabled
    Trigger:         Any probe

  Probes:
    probe0 [4]:      sim_state         - Simulation FSM state
    probe1 [10]:     agent_idx         - Current agent index
    probe2 [32]:     lfsr_state        - Random number generator state
    probe3 [8]:      trail_data_debug  - Trail memory data
    probe4 [10]:     pixel_x           - VGA X coordinate
    probe5 [9]:      pixel_y           - VGA Y coordinate
    probe6 [1]:      frame_start       - Frame start pulse
    probe7 [1]:      sim_running       - Simulation active

  Purpose:
    Captures waveforms of key internal signals for debugging. Useful for
    verifying FSM behavior, agent processing, and memory access patterns.
    Can trigger on specific conditions (e.g., specific sim_state).

  Resource Usage (estimated):
    LUTs:    ~300
    FFs:     ~400
    BRAM:    9 (36Kb BRAMs for 4096-sample capture depth)

DEBUG WRAPPER MODULE: debug_wrapper.sv
────────────────────────────────────────────────────────────────────────────

  Location: src/debug_wrapper.sv
  Purpose:  AXI-Lite slave that interfaces between JTAG-to-AXI and design

  Functions:
    1. AXI-Lite slave state machine
    2. Trail memory read arbiter
    3. Control/status register implementation
    4. VIO signal routing
    5. Frame capture sequencing

  Memory Map Implementation:
    0x0000_0000 - 0x0004_AFFF: Trail memory (307200 bytes)
    0x0010_0000:               Control register
    0x0010_0004:               Status register
    0x0010_0008:               Frame count
    0x0010_000C:               Width (640)
    0x0010_0010:               Height (480)

  AXI-Lite State Machine:
    States: AXI_IDLE, AXI_READ_TRAIL, AXI_READ_WAIT, AXI_READ_RESP, AXI_WRITE_RESP

    Read Transaction Flow:
      1. AXI_IDLE: Wait for arvalid
      2. AXI_READ_TRAIL: Assert trail memory read
      3. AXI_READ_WAIT: Wait for BRAM latency (1 cycle)
      4. AXI_READ_RESP: Return data on rdata, wait for rready

    Write Transaction Flow:
      1. AXI_IDLE: Wait for awvalid && wvalid
      2. Update control register if addr == 0x0010_0000
      3. AXI_WRITE_RESP: Return response on bresp


TRAIL MEMORY ACCESS
────────────────────────────────────────────────────────────────────────────

  Memory Type:      Inferred block RAM (BRAM)
  Organization:     Simple dual-port
  Size:             307200 bytes (640 x 480)
  Data Width:       8-bit
  Address Width:    19-bit

  Port A: VGA Controller (read-only, 25 MHz pixel clock)
  Port B: Agent Processor (read/write, 100 MHz system clock)
  Port Debug: Debug Wrapper (read-only, 100 MHz system clock)

  Address Calculation:
    linear_addr = y * 640 + x
    Valid range: 0 to 307199 (0x00000 to 0x4AFFF)

  Access Method via JTAG:
    1. Issue AXI read transaction with address in range 0x0000_0000 - 0x0004_AFFF
    2. Debug wrapper translates to trail memory address
    3. BRAM read takes 1 cycle
    4. Data returned on AXI rdata channel
    5. Multiple reads can be pipelined for burst transfers


SIMULATION CONTROL
────────────────────────────────────────────────────────────────────────────

  Freeze Mechanism:
    Signal: debug_freeze
    Sources: VIO probe_out1 OR control register bit 0 (OR'd together)
    Effect:  Pauses simulation state machine while high
             LFSR stops advancing
             Agent processing halts
             Trail memory remains stable for coherent reads

  Frame Synchronization:
    Signal: frame_start (1 clock pulse at start of each VGA frame)
    Frequency: ~60 Hz
    Counter: 32-bit frame_count register increments on each pulse
    Usage: Synchronize captures to frame boundaries


================================================================================
  USAGE WORKFLOWS
================================================================================

WORKFLOW 1: Interactive Debugging with Vivado Hardware Manager
────────────────────────────────────────────────────────────────────────────

  1. Program FPGA with debug bitstream:
     vivado -mode batch -source program_fpga.tcl

  2. Open Vivado Hardware Manager:
     vivado -mode gui
     Open Hardware Manager → Auto Connect

  3. Access VIO:
     Window → Dashboard
     Find "debug_vio" in dashboard
     Monitor probe_in0 (capture_done), probe_in1 (frame_count)
     Control probe_out1 (sim_freeze), probe_out3 (read_addr)

  4. Access ILA:
     Window → Hardware
     Select ILA core
     Configure trigger conditions
     Run trigger and capture waveforms

  5. Read Memory via JTAG-to-AXI:
     In TCL console:
       set jtag_axi [get_hw_axis hw_axi_1]
       create_hw_axi_txn read_txn $jtag_axi -address 0x00000000 -len 1024 -type read
       run_hw_axi read_txn
       set data [get_property DATA [get_hw_axi_txn read_txn]]


WORKFLOW 2: Automated Frame Capture with Python
────────────────────────────────────────────────────────────────────────────

  1. Import FPGA controller:
     from fpga_controller import SlimeFPGAController
     fpga = SlimeFPGAController()

  2. Capture frame:
     frame = fpga.capture_frame()

  3. Save to file:
     from PIL import Image
     img = Image.fromarray(frame, mode='L')
     img.save('fpga_frame.png')

  4. Compare with Python simulator:
     import numpy as np
     diff = np.abs(frame.astype(int) - python_frame.astype(int))
     max_error = np.max(diff)
     print(f"Max pixel difference: {max_error}")


WORKFLOW 3: Regression Testing
────────────────────────────────────────────────────────────────────────────

  1. Run Python reference simulator:
     python python_reference.py --seed 0xDEADBEEF --frames 100

  2. Program FPGA with same seed:
     # Use BTNL button to set seed, or write to control register

  3. Run both for N frames:
     for frame_num in range(100):
         fpga_frame = fpga.capture_frame()
         python_frame = sim.get_frame()
         diff = compare_frames(fpga_frame, python_frame)
         log_difference(frame_num, diff)

  4. Analyze results:
     plot_error_over_time(log_data)
     identify_divergence_point()

KNOWN ISSUES:
────────────────────────────────────────────────────────────────────────────

  1. Issue: JTAG read latency
     Description: Reading 307KB via JTAG can take 20-50ms
     Workaround: Freeze simulation during capture
     Status: Expected behavior due to JTAG bandwidth

  2. Issue: ILA triggers may miss fast events
     Description: 100 MHz sampling may miss single-cycle signals
     Workaround: Use longer pulse signals or multiple trigger conditions
     Status: Limitation of ILA depth vs frequency

  3. Issue: VIO probe updates are not instantaneous
     Description: ~100ms delay between setting probe_out and effect
     Workaround: Poll probe_in to confirm changes applied
     Status: Normal VIO behavior

================================================================================
  REBUILD COMMANDS
================================================================================

To rebuild the design with debug IPs from scratch:

  1. Clean previous build:
     rm -rf vivado_project_debug/

  2. Create project and add IPs:
     vivado -mode batch -source add_ip_cores.tcl

  3. Build bitstream:
     vivado -mode batch -source rebuild_with_ips.tcl

  4. Program FPGA:
     vivado -mode batch -source program_fpga.tcl


Alternatively, use the consolidated build script:

  cd rtl/
  vivado -mode batch -source scripts/build_debug.tcl


To rebuild just the bitstream (if IPs already exist):

  vivado -mode batch -source rebuild_with_ips.tcl
